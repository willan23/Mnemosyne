### Manhã (prioridade)

#### 1. Deploy functions + rules + indexes

O root `npm run deploy` faz hosting + firestore + storage e **não** faz functions. As callables P2 e a `publicApi` podem estar só no disco.

**Comandos** (em `W:\real\Mnemosyne`):

```powershell
cd functions
npm test
cd ..
firebase deploy --only functions,firestore:rules,firestore:indexes
```

Alternativa: `npm run deploy:all` (`deploy.ps1`) se quiseres hosting no mesmo passo. Não mexer em Stripe secrets.

**Checklist no Firebase console — feito quando:**

| Verificar | Critério |
|---|---|
| Functions `europe-west1` | `createTeam`, `lookupTeamInvitee`, `inviteMember`, `acceptInvite`, `leaveTeam`, `deleteTeam`, `publicApi`, `createApiKey`, `listApiKeys`, `revokeApiKey` |

#### 2. App Check (P0 residual de confiança)

Cliente já chama `initAppCheckIfConfigured()` se existir `VITE_FIREBASE_APPCHECK_SITE_KEY`. Provider default: **reCAPTCHA v3 clássico**. Enterprise só com `VITE_FIREBASE_APPCHECK_PROVIDER=enterprise`.

| Passo | Detalhe |
|---|---|
| Consola reCAPTCHA | https://www.google.com/recaptcha/admin → **v3** (não Enterprise). Domains: `mnemosyne-one.com`, `www.mnemosyne-one.com`, `mnemosyne-one.web.app`, `localhost`. |
| Firebase App Check | App web → provider **reCAPTCHA v3** → colar site key. Modo **Monitor**. |
| Env | `VITE_FIREBASE_APPCHECK_SITE_KEY` em `frontend/.env` + secret GitHub. |
| Rebuild hosting | A env só entra no bundle depois de `npm run build` + deploy hosting. |
| Se Enterprise está “desactivado” | Ignora — não precisas de Enterprise. Usa v3 clássico. |
| Não fazer | `enforceAppCheck` global. Parte Tauri, clipper, `publicApi` Bearer. |

Desktop: App Check para Tauri é provider custom ou debug tokens. Fica para a semana, depois do monitor web estar verde.
